# Обоснование конфигурации инфраструктуры (Terraform + Yandex Cloud)

Документ обосновывает выбор ресурсов, параметров и архитектурный подход к развертыванию инфраструктуры.

## 1. Выбор ресурсов и параметров

| Ресурс                                    | Назначение                | Обоснование выбора                                                                                                                                                                                                                          |
| ----------------------------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `yandex_vpc_network` / `subnet`                               | Сеть и подсети          | Изоляция трафика.<br />Разделение Web (`192.168.10.0/24`) и DB (`192.168.20.0/24`) уровней для безопасности.                                                                                             |
| `yandex_compute_instance`                                       | Виртуальные машины | **2 vCPU / 2 GB RAM**: баланс стоимости и производительности для старта. <br />Приоритет горизонтальному масштабированию вместо вертикального.    |
| `boot_disk`                                                     | Загрузочный диск     | **15 ГБ**: достаточно для ОС (Ubuntu), <br />логов и приложения с запасом на обновления.                                                                                                          |
| `network_interface` (NAT)                                       | Доступ в интернет    | `nat = true`: позволяет VM скачивать обновления и артефакты, <br />оставаясь недоступными извне напрямую.                                                                          |
| `yandex_mdb_postgresql_cluster`                                 | База данных               | Управляемый сервис снижает операционные затраты.<br />Конфигурация **s2.micro** с узлами в разных зонах (HA) обеспечивает отказоустойчивость. |
| `yandex_vpc_security_group`                                     | Безопасность            | Минимально необходимые правила.<br />SSH (22), HTTP (80), HTTPS (443). <br />В продакшене доступ SSH должен быть ограничен по IP.                                                          |
| `yandex_storage_bucket`                                         | Хранилище                  | Для state-файлов Terraform и артефактов.<br />Имя с суффиксом (`random_id`) предотвращает конфликты.                                                                                                |

### Сетевая архитектура

- **Мультизональность**: Подсети и узлы БД распределены по зонам `ru-central1-a` и `ru-central1-b`. Это обеспечивает доступность при сбое одной зоны.
- **Изоляция**: Разные CIDR-блоки для уровней Web и DB предотвращают случайный доступ к данным.

## 2. Подход IaC и декларативность

Использование Terraform и декларативного стиля конфигурирования обеспечивает следующие преимущества:

### Воспроизводимость

- **Единый источник истины**: Файлы `.tf` полностью описывают инфраструктуру. Любое окружение (dev, stage, prod) разворачивается идентично.
- **Идемпотентность**: Повторный запуск `terraform apply` не ломает систему, а приводит её к описанному состоянию, устраняя конфигурационный дрейф.
- **Документация**: Код инфраструктуры сам служит актуальной документацией архитектуры.

### Масштабируемость

- **Горизонтальное масштабирование**: Добавление мощностей сводится к изменению переменных (например, количества инстансов), а не ручной настройке серверов.
- **Гибкость**: Изменение параметров (размер диска, версия БД) применяется централизованно через код.
- **CI/CD интеграция**: Инфраструктура версионируется в Git, что позволяет внедрить автоматическое тестирование и развертывание изменений.

### Операционная эффективность

- **Автоматизация**: Исключаются ручные действия в консоли, снижая риск человеческой ошибки.
- **Безопасность**: Доступы регулируются через IAM-роли и Security Groups в коде, что упрощает аудит.

## 3. Итог

Конфигурация спроектирована с учетом баланса между

- **cost-efficiency** (легкие VM, управляемая БД),
- **безопасностью** (изоляция подсетей, NAT)
- и **надежностью** (мультизональность).

Применение IaC гарантирует, что инфраструктура остается воспроизводимой, масштабируемой и легкой в поддержке по мере **роста проекта**.
